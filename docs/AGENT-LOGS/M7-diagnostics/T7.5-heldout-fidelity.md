**Decisions taken during the work** (each with the alternative rejected and why):
- **R⁻ features are a row slice of the full-`ref` features**, which are computed once per dataset
  (`ReferenceSets.r_minus_rows`). Rejected: a separate R⁻ forward pass, because the features are
  per-image and the slice is the same numbers at half the cost. Accepted by main.
- **The reference order is `np.sort(splits["ref"])`**, the order `run_eval._dataset_views` uses
  for the production cache, so anchor (a) compares row for row. Rejected: the splits.json order,
  which would misalign anchor (a).
- **R⁻ selection uses one rule per modality.** MRI drops every `ref` row of a seed subject (by
  subject); photographs drop the `seed` images (by image). Both are then cross-checked: no R⁻ row
  may belong to a seed subject. Rejected: a single by-subject rule for both, which on
  photographs gives the same set but does not express the ticket's "by image" rule.
- **The scratch work is extract → features → delete.** Each run's needed members are streamed
  once from its tar with `tarfile`, which seeks over the rest, so one read per tar. The H and F
  features are cached as `.npy`; a per-run sidecar JSON is written last and marks completion.
  The sample arrays are deleted after their features are saved. Rejected: keeping the arrays
  (about 150 MB per run on the shared disk). The grid needs only 8 seeds × 2 samples per run,
  saved as a small `.npz`.
- **Anchor runs are materialised by the anchors step and reused by the full run** (cache hit:
  `lsun_church_A3_s1` took 17 s in the full run). Rejected: recomputing.
- **Anchor (a) is reported without a gate; anchor (b) is gated as specified.** The ticket gives
  (a) no threshold. Accepted by main.
- **The CLI writes only the JSON and the grid into `--out`.** The markdown tables go to
  `<work>/tables.md` and the README is hand-written from them. Rejected: a generated README,
  because a re-run would overwrite the hand-written description and caveats.
- **OASIS-1 applies the rule with "all seeds" = 2; photographs apply it mechanically, labelled
  descriptive.** Accepted by main.
- **Extra check beyond the ticket.** The F-versus-full-`ref` metrics are compared with the stored
  `final.json` for all 24 runs, not only the 2 anchor runs. The worst |Δ| is 0.0050, and every
  KID falls inside its stored interval. The comparison costs nothing because the features exist.

**Rulings by main, 2026-10-03, made before any contrast was computed** (in reply to the agent's
message about the KID fallback):
1. *Amendment to step 6.* When rule 1 fires on precision, the WHOLE rule (rule 1 included) is
   applied to KID with gain A0 − A3. If the KID comparator also fails, the outcome is "not
   evaluable on precision or KID"; otherwise rules 2–4 apply to KID. This is implemented in
   `read_rule`, with a unit test of that path
   (`test_read_rule_not_evaluable_on_precision_or_kid`). `kid_comparator_gain_positive` is kept
   in the JSON. The README states the amendment and its date.
2. *R5 sensitivity is H only.* Per seed $\Delta_H(\text{R5})$, its mean and sign agreement
   (`sign_summary`). There is no ratio rule against a $G_F$ on R5. F against R5 is printed as
   descriptive with the contamination caveat.

**Assumptions proceeded on:**
- The production step of every run is the last step whose held-out and final sets are both in
  the tar (`_find_step`). It is 60,000 for all 24 runs, equal to `final.json`'s `step`.

## 5. Results of the ticket

Folder: `docs/RESULTS/heldout_fidelity/` (`heldout_fidelity.json`, `README.md`,
`heldout_grid.png`).

**IXI reading (primary, precision against R⁻): "the fidelity gain generalises to unseen seeds".**
$\Delta_F$ = +0.1535, +0.0915, +0.0605 ($G_F$ = +0.1018); $\Delta_H$ = +0.1605, +0.0650, +0.0670
($G_H$ = +0.0975 ≥ 0.5 $G_F$ = +0.0509). The KID fallback was not needed
(`kid_comparator_gain_positive` true).

- A0 sanity: the IXI A0 precision gap $m_F - m_H$ is +0.012, −0.027 and −0.003 (mean −0.006).
- R5 sensitivity, IXI H: precision $\Delta_H$ = +0.204, +0.148, +0.127 (all > 0); KID −0.0056,
  −0.0075, −0.0033 (all < 0, A3 better).
- OASIS-1 (2 seeds, descriptive): "generalises". $G_H$ = +0.1340 against $G_F$ = +0.1292. Its KID
  on H is worse for A3 (+0.0089, +0.0143) on R⁻ and better on R5 (−0.0258, −0.0217).
- Churches (mechanical, descriptive): "generalises". $G_H$ = +0.0775 against $G_F$ = +0.0868.
- Bedrooms (mechanical, descriptive): "generalises". $G_H$ = +0.1118 against $G_F$ = +0.1115.
- Descriptive finding to flag: on IXI, A3's **KID** gain shrinks from −0.0298 on F to −0.0041 on
  H (14%). Both W/8 arms show a KID gap $m_F - m_H$ of ≈ −0.036 and H recall of 0.08–0.10,
  against −0.011 and 0.17–0.29 for A0. This is consistent with W/8 chains collapsing onto the 40
  prior layouts in H, which distribution metrics penalise and precision does not.

  not a pure "training versus unseen" contrast; A0 is the control. Severity: low; the caveat is
  stated in the README.
