`lsun_church` (r128: the same 4,000 photos, whole scene resized to 128²; n32k: the same 192²
native crops and the identical 800/40 ref/seed images, with 32,000 train images), teach the config
factory to train arm A0 on them (128² with a new frozen `log_W2_128` schedule) without changing
any byte of the 30 production configs, smoke both cells on CPU and on an A100, and stop with the
exact production command for the two 60k runs until `main` says GO.

   append-one-entry path to `ihdm.cli.build_schedules`, build `log_W2_128` with the same
   `_entry → build_schedule → log_schedule → save_schedule` path as `log_W2`; test.

**Decisions taken during the work** (each with the alternative rejected and why):

- **`log_W2_128` is appended with a new `build_schedules --add <name>` path, not by a full
  rebuild.** The full rebuild (`build`) rewrites every entry of `schedules.json` (new `created`,
  new `git_sha`) and re-fits the five matched schedules; the ticket requires every existing entry
  byte-identical. `--add` runs the same `_entry → build_schedule → log_schedule → save_schedule`
  path that built `log_W2` and re-serialises the index with `build`'s format
  (`json.dumps(indent=2, sort_keys=True) + "\n"`), so the diff is 23 insertions, 0 deletions.
  Rejected hand-writing the entry (no provenance, easy to get the hash wrong) and adding the name
  to `SCHEDULES` (a later `--force` rebuild would then re-stamp it with the frozen ones).
- **`TERMINAL_BLURS` gains 64.0** rather than a separate validator for the diagnostic: the only
  consumer is `_structural_problems` (shared by `save_schedule` and `validate_schedule`), and 64
  is the W/2 rule at width 128, not a new kind of schedule. 50 px is still rejected (tested).
- **The schedule was built after committing the code that builds it** (`c0d9f66`), so the
  entry's `git_sha` names a commit that contains the builder.
