## 2. Plan and decisions

**Restatement:** The octave-band split of `oct_rms_low`/`oct_rms_high` mislabels the 2-4 c/img
octave as carried by the σ_B,max = 24 prior (its d_K² there is ≤ 0.085, down to 0.008 at
2.8 c/img); replace it with a three-way split at 2 and 4 c/img. Two uncaught `ValueError`s
(a non-finite octave in `octave_summary`, a non-positive `variance_ratio` in `math.log10`)
currently escape `main` as tracebacks instead of becoming an `AnalysisError` (exit 1). The
existing tests never check computed values end to end, because the synthetic campaign's curves
are constant (NaN correlations). Regenerate `docs/RESULTS/exploratory/` from the real 30-run
results and record every changed number.

**Plan:**
1. Read the ticket, the module, its tests, `tables.py`'s `Results`/`AnalysisError`/`load_results`,
   the synthetic-campaign test fixtures, and the committed `exploratory.md`/`.json`.
2. Replace the two-band split with three (`oct_rms_prior` = 0.5-1 & 1-2, `oct_rms_mid` = 2-4,
   `oct_rms_high` = 4-96, numerically unchanged), updating the module docstring, `ENDPOINTS`
   labels/readings and the generated Markdown's definitions paragraph.
3. Wrap the two uncaught `ValueError` paths (`octave_summary`, `math.log10(variance_ratio)`) in
   helpers that raise `AnalysisError` naming the run id.
4. Add value tests: a hand-built single-run `Results` for `add_endpoints` (`lsd_late`, `log_vr`,
   `regen_ratio`, the three bands) and a constructed two-run checkpoint frame for `curve_summary`
   (peak step, variance ratio at the peak, within-run correlations), plus a test that `main`
   returns 1 on a results folder with `-inf` in one run's `final.json` octaves.
5. Run the fast `tests/analysis` suite, then the full fast suite.
6. Regenerate `docs/RESULTS/exploratory/` from the real results; diff `exploratory.json` with the
   band keys stripped against the committed version to confirm nothing else changed.
7. Write this log; commit code, then outputs, then the log last.

**Decisions taken during the work** (each with the alternative rejected and why):
- Wrapped the same non-finite-octave guard (`_octave_summary_or_raise`) into `checkpoint_frame`
  too, not just `add_endpoints` — rejected leaving `checkpoint_frame` unguarded, because it calls
  the identical `octave_summary` on `ckpt_<step>.json` records and would otherwise still leak a
  bare traceback from a corrupted checkpoint file; the ticket's own framing ("a non-finite octave
  error... escapes `main` as a traceback") is about the failure mode, not only the one call site
  named in the acceptance test. No contract, endpoint or output changes — only the error type.
- Built the `add_endpoints` value test against a hand-built `Results` object (frozen dataclass,
  minimal `frame` + a bare `final.json` on disk) instead of the synthetic 30-run campaign —
  rejected the campaign because its curves are constant by construction (the exact defect this
  ticket is fixing the absence-of-test for), and because `add_endpoints` only needs `frame`,
  `root` and `steps`, not a full collected folder.
- Reused `conftest.py`'s session-scoped `pristine_campaign` fixture (via a new module-scoped
  `collected_root` fixture that runs it through `collected_results` once) for the `AnalysisError`
  test, instead of building a third fresh campaign — rejected rebuilding, because
  `collected_results` with no `absent` runs is read-only on the campaign and the fixture is
  documented as "never modified"; the corrupted copy is made with `shutil.copytree` per test.
- Corrupted the *collected* `runs/<run_id>/final.json` directly (plain `json.dumps`/`write_text`,
  not `ihdm.metrics.io.write_json`, which refuses non-finite values by design) rather than the
  campaign's pre-collection shadow file — rejected editing the shadow via `Campaign.edit_json`,
  because `collect()`'s C6 check (`strict_json`) refuses `NaN`/`Infinity` tokens at collection
  time, so the corruption would fail collection itself instead of reaching `exploratory.py`.
