**Decisions taken during the work** (each with the alternative rejected and why):

- **`create_env.sbatch` uses `--constraint=download`, not `--constraint=cpu`.** Measured on the
  cluster: `sinfo -h -o "%20N %10c %10m %f"` shows exactly one node advertising the `download`
  feature, `picasso4` (64 cores, 250 GB, `cpu_partition`, `idle`), and the `picasso-sbatch` skill
  records it as "the node with outbound internet". `conda env create` and `pip install` must reach
  `conda-forge` and PyPI, and the skill states that Picasso compute nodes typically lack outbound
  internet. Requesting a generic `cpu` node was rejected because a network failure there would
  waste a queue slot and produce a half-built environment; `--constraint=download` makes the
  network a scheduling constraint rather than a gamble. The prompt's fallback (`tmux` + `nice` on
  the login node) was therefore not needed.
- **The environment is built with `conda env create -f environment.yml -p <prefix>`, not by
  cloning an existing env.** `IsalHG-tkde/scripts/tkde/picasso_env_setup.sh` clones `isalhg`,
  but that env is python 3.10 with a different dependency set; D8 pins python 3.11 and a
  torch/imaging stack that shares nothing with it, so a clone would only add mass to prune.
- **`pip install -e .` is run through the env's own interpreter** (`<prefix>/bin/python -m pip`)
  rather than after `conda activate`. Activation inside a non-interactive batch shell is the
  usual source of "installed into the wrong env" bugs; the absolute interpreter path cannot be
  ambiguous. `conda activate` is still done first so that any build step sees the env's compilers.
- **The import check pins `--constraint=a100 --gres=gpu:1` (untyped GRES).** Per the skill and
  `sinfo`, `exa[01-04]` advertise an untyped `gpu:8` with features `dgx,gpu,a100`, while
  `blk[01-02]` advertise `gpu:B200:8` with `dgx,gpu,b200`. `--gres=gpu:A100:1` matches nothing and
  bare `--constraint=dgx` would happily schedule onto a B200.
- **No `$LOCALSCRATCH` staging and no 2 h grouping for these two jobs.** The skill's
  `$LOCALSCRATCH` rule targets workloads writing thousands of small files, and its 2 h floor
  targets large arrays; `create_env` writes one conda prefix and `import_check` writes one
  20-iteration run directory. Both are one-off setup jobs, not a campaign. Recorded here because
  the skill asks for the deviation to be stated rather than left unsaid.
- **The import check runs the trainer at `batch_size=4`.** T2.1 measured ≈ 29 GB at batch 16 on an
  A100 40 GB; the point of this job is that the code runs, not that it fills the card.

**Assumptions proceeded on:**

- The Picasso clone can read the public GitHub repo over HTTPS without credentials. If SSH keys to
  GitHub are absent there, HTTPS is the documented fallback in the prompt. What breaks if wrong:
  the clone step; the fallback is an `rsync` of the worktree, which the prompt does not authorise,
  so `main` would have to be told.
- The `download` node's outbound access covers both `conda-forge` and PyPI. What breaks if wrong:
  `create_env` fails at the first download; the log says which host was unreachable and the
  login-node `tmux` fallback applies.
