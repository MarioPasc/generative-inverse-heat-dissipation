## 2. Plan and decisions

**Restatement:** Turn main's scratch scripts (`manifold_dim.py`, `manifold_dim2.py`,
`manifold_dim3.py` in main's scratchpad) into a tested library + CLI that computes the
Levina–Bickel MLE intrinsic dimension (k ∈ {5, 10, 20}, N ∈ {320, 1,000, 3,200}) and the PCA
participation ratio and components-for-variance of the four 3,200-image training splits, then
write the JSON, the figure and a README that states the ticket's reading and caveats.

**Plan:**
1. `ihdm/analysis/intrinsic_dim.py` (estimators, data loading, per-dataset analysis, reading
   checks, figure) and `ihdm/cli/intrinsic_dim.py` (exit codes 0/1/2).
2. Tests: the four ticket tests plus the formula by hand, subset/centring invariance, exit 1 and an
   end-to-end byte-stable run on small synthetic splits. Commit.
3. Real run (CPU, nice 19, 2 threads), compare with the scratch table (±1), view the figure, check
   byte stability by a second run. Commit results.
4. README by hand from the JSON. Full fast suite. Log; commit last.

**Decisions taken during the work** (each with the alternative rejected and why):
- One Gram matrix per dataset (N = 3,200); every random subset and the one-slice variant use the
  corresponding block of the full distance matrix — recomputing a Gram per subset rejected:
  Euclidean distances do not depend on the centring, so the block is identical (tested by
  `test_gram_distances_independent_of_centring_and_subset`) and the run costs one Gram per dataset.
- Subset draws: `np.random.default_rng(2026)` re-created per dataset; for N = 320 then N = 1,000,
  ten `rng.choice(3200, N, replace=False)` over positions in the sorted train list; the same subsets
  serve every k — a single generator across datasets rejected because a dataset's numbers would
  then depend on the order of the others. Consequence: the random-320 numbers are means over ten
  subsets and do not equal the scratch's single draw (16.5 / 19.1 / 21.1 / 19.5), which the ticket
  does not require to be reproduced.
- sd over subsets is the sample sd (ddof = 1), stated in the JSON `method.sd`.
- Neighbours by `np.partition` + sort of the first k, instead of a full row sort — same values,
  fewer operations; checked against the explicit-loop formula (`test_mle_matches_formula_by_hand`).
- A zero nearest-neighbour distance (duplicate images) raises `IntrinsicDimError` rather than
  returning inf/NaN.
- Synthetic test uses Gaussian coordinates on the subspace (noise σ = 1e-3): estimates 5.0–5.1 for
  d = 5 and 9.2–9.7 for d = 10 across k ∈ {5, 10, 20}. Uniform-cube coordinates were also within
  20% (8.2–8.5 for d = 10) but sit closer to the bound because of the boundary bias.
- Figure: one panel (k = 10, mean ± sd against N on a log axis), MRI solid lines, photographs
  dashed, IXI/Churches black and OASIS/Bedrooms grey, distinct markers; hollow markers at N = 320
  for the MRI one-slice-per-subject variant; legend to the right. All fonts 7 pt (the house style's
  6.5 pt ticks are overridden), and a layout audit raises if the size or font limits are broken.
- README written by hand from the JSON; the JSON also carries a `reading` block with the three
  statements checked as booleans, so a rerun shows whether the README's reading still holds.

**Assumptions proceeded on:**
- "Slice 5" is the `slice` column of `index.csv` (values 0–9 per subject); the code asserts that it
  yields exactly one image for each of the 320 `train_subjects`.
