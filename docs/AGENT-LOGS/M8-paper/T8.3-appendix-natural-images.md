**Decisions taken during the work:**
- **Precision source: `<results>/index.csv`, not `tables.json`.** `tables.json` has no precision
  anywhere (tables 1a–1c carry LSD, KID, FID, recall, coverage). The per-run `precision` column of
  `index.csv` (the same values as `exploratory.json` `per_run` and `results_discussion.md` §4) is
  averaged per (dataset, arm) cell. Alternative (hard-code 0.12 / 0.63–0.84) rejected: violates
  "every number read from a file". Stated in `A1.md`.
- **"At most 0.12"**: the photograph maximum is 0.1205 (Bedrooms matched, seed mean; seed 1 alone is
  0.1305). The text prints it to two decimals; `A1.md` gives 0.1205 and its cell.
- **Caption wording on the noise.** The ticket asks for "dominated by irreducible training noise".
  The caption says instead: "About 98% of each level's regression target is the added training
  noise and only about 2% the deblurring that forms the image, so the loss is dominated by
  denoising: its plateau shows that the optimisation settled, not that the samples converged."
  Reason: the network sees the noisy input, so most of the noise term is *not* irreducible in the
  loss. The step-0 loss (3.80, `lsun_church_A0_s1`) is close to $N\sigma^2 = 192^2 \times 0.01^2 =
  3.69$ (the target energy), and the final smoothed loss is 0.324, i.e. the model removes about
  91% of it (LIKELY: assumes the logged loss is a per-image sum over pixels, which the step-0 value
  supports). "Irreducible" would overstate; the required message (loss dominated by noise, plateau
  ≠ sample convergence) is kept. Flag for main/Mario.
- **The 98% is a cited constant** (`NOISE_SHARE_CITED`, source `learning/03` §6 eq. 6.5), the only
  number in caption/text not read from a generated file besides Table A1's fixed facts. Reading it
  from the learning note by regex was rejected as fragile (outside the code repo).
- **Plateau rule** (pre-declared in the module, not tuned to the draft): first logged step after
  which the seed-mean running mean stays within 10% of its mean over the last 5,000 iterations;
  later dataset; rounded up to 5,000. Raw: Churches 21,350, Bedrooms 23,050 → 25,000 it = 125
  epochs. `A1.md` also reports that the loss still falls 6.7% (Churches) and 6.8% (Bedrooms) from
  25k to 60k, so "levels off" is not "flat".
- **Seed = first index of `eval_seeds_500.npy`**: the file is not on the local disk, so the CRN
  assertion additionally requires the LSD set's `seed_idx` sha256 to equal `summary.json`
  `seed_lists.intermediate_sha256` (the frozen list), and position 0 is shown. Both datasets show
  image 1180: their 500-seed lists are identical (same sha256 `50eda5fa…`; drawn with rng 2026
  from equally sized train splits).
- **CRN assertion** (beyond the ticket's minimum): per checkpoint, `request.json` step equals the
  checkpoint, set `lsd`, `n_per_seed` 1, same `rng_seed` and `batch_size`, identical `seed_idx` and
  seed images, signature `seed_idx_sha256` equals the stored indices, equal sample shapes.
- **Table A1 "ours" column cross-checked** against every A0 run's `config.json`, `summary.json`,
  `manifest.json` (n_train 3200, 1 channel, 192², channel_mult (1,2,2,2), 4 res-blocks, 61 M
  params, K 200, lr 1e-4, batch 16, 60k) and iterations per epoch = 3200/16 = 200 asserted; a
  mismatch exits 1.
- **Extra optional CLI flag `--photo-diagnostic`** (defaults to the repo file) so tests can supply a
  synthetic one; the frozen contract's flags are unchanged.
- **Histories** are read as fig. 7 reads them, with `validate_run.canonical_records` applied again
