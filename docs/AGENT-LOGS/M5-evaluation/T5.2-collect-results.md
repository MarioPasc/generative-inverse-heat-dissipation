**Decisions taken during the work** (each with the alternative rejected and why):
- **Gate JSON read as flat** (`step_a`, `step_b`, `lsd_a`, `lsd_b`, `difference{…}`, `extend`,
  `n_seeds`, `amp`, `seed_list_sha256`), verified on the real
  `~/execs/ihdm/eval/gate/ixi_A0_s1_amp-fp16_gate.json` (2026-09-28). The prompt described a
  top-level `gate` key; that is the shape of `summary["gate"]` in `evaluate_run`, not of the gate
  file. Rejected: coding against the prompt's description, which would fail on every real gate.
- **Two checks beyond the ticket's seven**: C8 (the tar's `summary.json` equals the plain copy
  byte for byte; sidecars and the final grid present; tar readable) and C9 (gates). Rejected:
  folding them into C1-C7, which would make a check's verdict mean two unrelated things.
- **`FAIL` vs `MISSING`.** A contradiction in an input that exists is always a failure; an absent
  input is `MISSING`, a failure unless `--allow-missing`. Under `--allow-missing` the folder is
  published whatever the verdict (it is a dry run) but marked `"complete": false`. Exit codes:
  0 complete, 1 fail or absent input, 2 unusable arguments, 3 partial under `--allow-missing`.
  Rejected: exit 0 on a partial dry run, which a script could mistake for a collection.
- **Staging as a sibling directory** `.<out>.partial-<pid>`, `os.rename` at the end, `rmtree` in
  a `finally`. Rejected: staging in `/tmp`, because `rename` across filesystems is not atomic
  (`/tmp` vs `$HOME` on Picasso). `--out` must not exist; results are never overwritten.
- **Byte copies.** Every published file is a byte copy of its input; `metrics.canonical.jsonl`
  holds the raw lines that `canonical_records` keeps, mapped through the identity of the parsed
  objects (the function keeps the same dicts). Rejected: re-serialising with `json.dumps`, which
  changes spacing and float text and would break a sha comparison with the archive.
- **The gate cells and pairs**: cells 0 and 3 (`gate.sbatch` `GATE_CELLS=0:3`, `--gate-cells`)
  must hold 35k/40k (legacy) and `(n_iters - 5000, n_iters)`. Gates of another precision are
  listed as ignored, not failed. A legacy and a pair-named file of the same pair is a failure
  (two sources for one number).
- **Private import `check_array._recipe_hash`** for C5, as `check_array` itself imports private
  helpers of `validate_run`. Rejected: a second copy of the recipe-hash rule, which could drift.
- **Synthetic fixtures from real writers**: one real `evaluate_run` call (T4.3's tiny run, cached
  per process, ≈ 7 s) supplies the `summary`/`ckpt`/`final` schemas and the real `.npy`
  sidecars; `InceptionResult.to_json` and `GateResult.to_json` supply the Inception block and the
  gates; T3.5's `make_run` supplies 60k run directories extended by a resume; run 11 gets its real
  shape (6 kept skips, an abort at 30,136 abandoned by a resume at 30,001). Rejected: hand-written
  JSON, which would test the collector against my reading of the schema instead of the schema.
- **`index.csv`** carries the per-step LSD (`lsd_005000` … `lsd_060000`) and, per gate pair
  found, `diff/ci_low/ci_high/extend`, so T6.1 can compute T_tau and quote the gates from the
  index alone. Rejected: a single `gates` string column, which a CSV reader cannot use directly.
