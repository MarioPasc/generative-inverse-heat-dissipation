**Decisions taken during the work** (each with the alternative rejected and why):

- **D-T4.3-1 — the synthetic run of `tests/metrics/test_run_eval.py` uses 96² images, not the 32²
  of the T2.2 fixture.** The ticket asks for the T2.2 fixture at 32². That cannot work:
  `ihdm.metrics.spectral._octave_difference` raises `MetricError` when an octave bin holds no
  mode, and the octave grid of `05` §1 runs to 96 cycles per image. At `W = 32` the largest radial
  index is `sqrt(2)·31 = 43.8`, i.e. 21.9 cycles per image, so the two coarsest-resolution octaves
  `32-64` and `64-96` are empty and every `lsd()` call raises. The smallest square grid that
  populates the `[64, 96]` octave needs `sqrt(2)(W-1) >= 128`, i.e. `W >= 92`; 96 is the next size
  that also divides by the smoke config's single downsampling stage. *Alternative rejected:*
  patching `lsd` to tolerate empty octaves — `spectral.py` is T4.1's and read-only for me, and the
  behaviour is deliberate. *Alternative rejected:* testing `run_eval` without LSD — that is the
  metric the command exists for.
- **D-T4.3-2 — the synthetic run has 14 subjects, not the fixture's 8.** `memorisation_ratio`
  needs a held-out corpus = `ref` minus the seed subjects. With 8 subjects and `n_seed=2` the
  `ref` split *is* the two seed subjects, so the held-out corpus is empty. 14 subjects give
  11 train / 3 ref / 2 seed subjects, i.e. a non-empty held-out corpus of one subject.
  *Alternative rejected:* reusing `tests/sampling/conftest.py::build_dataset` unchanged — it is
  T2.2's file and it produces the degenerate split.
- **D-T4.3-3 — the canonical seed lists are always written at their full size (500 / 2000) and the
  `--n-lsd` / `--n-final` flags take a prefix of them.** D17 fixes one list per dataset; a run
  evaluated with fewer samples must still use *the same noise streams* as a full run, which a
  prefix guarantees and an independent smaller draw does not. The intermediate list is capped at
  the training-split size when the split holds fewer than 500 images (the synthetic fixture), and
  the effective size is recorded in the sidecar. *Alternative rejected:* writing a list sized to
  `--n-lsd` — two runs evaluated at different counts would then not be comparable, and the file
  name `eval_seeds_500.npy` would lie.
- **D-T4.3-4 — `paired_lsd_gate` recomputes the bootstrap LSD through a fast path that works from
  precomputed per-image DCT coefficients rather than calling `lsd()` 2 × `n_boot` times.** Calling
  `lsd()` per resample costs `2 · n_boot` transforms of the 500-image sample stack *and* of the
  800-image reference stack (1000 × 1300 DCTs at 192², hours). The fast path stores
  `C_k = DCT(x_k - mean(x_k))` once per stack and forms
  `P_B = <C²>_B - (<C>_B)²`, which is algebraically identical to `mode_power` on the resampled
  stack (the DCT is linear, so centring across the stack in pixel space and in coefficient space
  agree — `mode_power`'s own docstring makes the same argument). The reference profile is computed
  once. `tests/stats/test_bootstrap.py::test_gate_point_estimate_equals_the_frozen_lsd` asserts the
  identity-resample value equals `lsd(a, ref).lsd - lsd(b, ref).lsd` to 1e-12, so the fast path is
  pinned to the frozen metric. *Alternative rejected:* a smaller `n_boot` — the spec fixes 1000.
- **D-T4.3-5 — the gate statistic is the bootstrap of the *aggregate* LSD over a resampled seed
  subset, not of a per-sample LSD.** `05` §8a words the gate as "the per-sample log-spectral
  distance ... computed for the same 500 seeds", which would be the LSD of a single image against
  the reference profile; the delegation prompt words it as "compute `lsd` on the SAME resampled
  subset of both sample sets". The two differ: `P` of `05` §1 is a *variance across the stack* and
  is undefined for one image (`lsd` itself demands `N >= 2`), so the per-sample reading is not
  implementable against the frozen metric. I implemented the prompt's reading and flag the
  wording of §8a in §6 for `main`.
- **D-T4.3-6 — `kid_from_features` seeds the legacy global numpy RNG around `cleanfid.fid.kernel_distance`.**
  The released `kernel_distance` draws its 100 subsets with the *global* `np.random`, so two calls
  give two answers. The wrapper saves `np.random.get_state()`, seeds it from `rng_seed`, calls the
  frozen function and restores the state, so KID is reproducible without reimplementing the
  estimator. *Alternative rejected:* reimplementing the polynomial-kernel MMD — the ticket says
  to reuse `cleanfid.fid`.
- **D-T4.3-7 — the per-sample arrays never enter the JSON.** `MemResult.per_sample_d` /
  `per_sample_nn` (2000 numbers each) and `PcaResult.components` / `train_scores` go to `.npy`
  files beside `final.json` (T4.2 §6 asked for exactly this); the PCA seed and sample scores stay
  in the JSON as lists, as the prompt requires. The `InheritedResult` radial arrays are written
  with their empty bins **dropped** (the `centres` array is written alongside so the curve stays
  interpretable), because `write_json` refuses `nan` (T4.1 §6).
- **D-T4.3-8 — `--ckpts all` falls back to every available EMA checkpoint when none of the eight
  evaluated steps {5000, …, 40000} exists.** The pilot's checkpoints are at 250/500/750, and a
  hard failure there would make `all` untestable outside a real 40k run. The fallback logs a
  warning and records `ckpt_selection: "all-available"` in the summary.

**Assumptions proceeded on:**

- The `ref` reference stack of `05` §2 is `splits["ref"]` (800 rows = the 80 held-out subjects,
  of which `splits["seed"]`'s 400 rows are the 40 seed subjects). Verified against
  `ixi/splits.json`. The held-out corpus of the memorisation denominator is
  `splits["ref"] \ splits["seed"]` (400 rows), i.e. the `index.csv` rows whose `split == "ref"`.
  If this is wrong, `M`'s denominator changes but nothing else does.
- `kid` is reported as the headline and `fid` always carries `n_reference`; no absolute FID is
  interpreted. This is `05` §7 and needs no assumption, but the JSON schema encodes it
  (`inception.n_reference` is mandatory).
