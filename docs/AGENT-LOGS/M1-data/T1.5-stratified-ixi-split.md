**Decisions taken during the work** (each with the alternative rejected and why):
- **Apportionment algorithm: largest-remainder (Hamilton), ties broken by sorted label order,
  reused for both the train/ref split and the seed draw** — alternative rejected: a simple
  `round()` per stratum, rejected because independent rounding does not guarantee
  `sum == round(train_frac * N)` (the ticket's explicit requirement); a stochastic tie-break was
  rejected in favour of the deterministic `sorted(order)` tie-break so the result depends only on
  `rng_seed`, not on dict ordering.
- **`strata=None` keeps the exact original code path (same `rng.permutation` /
  `rng.choice` calls, same order), branching *before* any RNG draw** — alternative rejected: a
  single unified stratified code path with one all-in-one-bucket "stratum", rejected because it
  changes the RNG call sequence relative to the frozen implementation and would break the
  byte-for-byte regression the ticket demands (verified: it does — an earlier draft of this
  function using that shape failed the archived-dataset regression test before this rewrite).
- **`ihdm/cli/preprocess_mri.py`'s `split_rule` provenance string is derived from `args.cohort`,
  not from `splits["rule"]`** — alternative rejected: use `splits["rule"]` directly (simpler, one
  fewer literal to keep in sync), rejected only because `_build_meta` does not currently receive
  `splits`, and changing its signature was judged wider than needed; documented here so a future
  editor knows `splits["rule"]` is the source of truth if the two strings should drift.
- **Rebuilt in two passes (`--no-n4` first, then the default N4 pass with
  `--sensitivity-copy`), after first deleting the stale
  `_sensitivity/ixi_no_n4/` directory** — required because `move_to_sensitivity` is idempotent
  (skips the move when the destination is already a non-empty directory); the destination held
  the *old*, pre-T1.5 uncorrected dataset, so without deleting it first the second pass would have
  silently discarded the freshly-built stratified uncorrected dataset instead of archiving it.
  `splits.json`/`meta.json` of the old `_sensitivity/ixi_no_n4` were copied to
  `docs/AGENT-LOGS/M1-data/T1.5-stratified-ixi-split.before/` before the deletion, per the
  ticket's evidence requirement.
- **`schedules/oasis1_W8.npy` reverted to its pre-rebuild bytes after `build_schedules --force`
  changed it unexpectedly (see §6, finding 1)** — `--force` recomputes all seven schedules in one
  pass and has no per-name selector; rather than accept a change to a schedule the ticket says must
  stay untouched, the five unaffected `.npy` files and their `schedules.json` entries were
  restored to `git show HEAD:...` byte-for-byte, keeping only `ixi_W2`/`ixi_W8` (files and JSON
  entries) from the fresh fit. Verified every `schedules.json` entry's `sha256` still matches its
  `.npy` file after the restore.
- **The site-mix-per-split table (data_profile.md §2.2) was added by hand to the *output* file,
  not by editing `ihdm/cli/profile_data.py`** — `profile_data.py` is not in this ticket's
