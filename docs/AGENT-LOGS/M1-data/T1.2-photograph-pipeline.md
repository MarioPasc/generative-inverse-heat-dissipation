**Decisions taken during the work** (each with the alternative rejected and why):

- **`PYTHONPATH=<worktree>` instead of `pip install -e .` from the worktree.** The prompt's
  bootstrap suggests `pip install -e .`, but the `ihdm` conda env already carries an editable
  install pointing at the *main* checkout, and peer T1.1 runs in the same env at the same time.
  Re-installing editable from `wt/T1.2` would silently redirect T1.1's `import ihdm` to my
  worktree for the rest of the wave. Rejected for that reason. `PYTHONPATH` takes precedence over
  the `.pth`-based editable install (verified: `ihdm.__file__` resolves to the worktree), and
  `pyproject.toml` already sets `[tool.pytest.ini_options] pythonpath = ["."]`, so `pytest` from
  the worktree root picks up the worktree package without any install at all.
- **Short side in `[192, 256)` is cropped without resizing.** The contract fixes two cases only
  (`== 256`: crop; `> 256`: resize to 256 then crop) and forbids resampling beyond that. For a
  short side between 192 and 256 the 192-px centre crop is still well defined, so it is taken
  directly. Rejected upsampling to 256, which would invent high-frequency content and break the
  "native pixels, no resampling" constraint of `00-overview.md` §3. Rejected rejecting the row,
  which would contradict "keep rows whose short side is >= 192 px" in the ticket. The case does
  not occur in either LSUN shard (every row has a 256-px short side).
- **Raw PNGs are the grayscale original at native size, not the 192 crop.** The existing 2000
  files are `Image.open(bytes).convert("L").save(...)` at the source resolution (verified:
  `00000.png` of both sets is 341x256 mode `L` and equals row 0 of the corresponding shard after
  `convert("L")`). New files continue exactly that rule so the raw folder stays one homogeneous
  source of truth and the 192 crop stays a derived quantity. Rejected saving crops, which would
  make the folder half-raw and half-processed.
- **Only accepted, de-duplicated rows get a raw PNG, numbered by accepted position.** This keeps
  `NNNNN.png` in bijection with `idx` in `index.csv`. Rejected numbering by shard row, which
  would leave gaps and break the continuation of the existing numbering.
- **The raw `NATURAL_CONTROLS/` PNGs are numbered by SHARD ROW, not by accepted index.** This is
  the decision the ticket did not anticipate, and it is forced by a real conflict between two of
  its own rules. The existing 2000 controls were fetched *without* a duplicate filter, so control
  PNG `r` is shard row `r` (verified by pixel equality). The frozen contract, however, requires
  SHA-1 de-duplication with replacement. Churches shard row 1855 is a byte-identical duplicate of
  row 1623, so from accepted index 1855 onward the accepted index is one less than the shard row,
  and every later index disagrees with the identically numbered control PNG. Numbering new files
  by accepted index would leave the folder with two meanings for one naming scheme (files
  00000-01999 meaning rows, files 02000+ meaning indices) and no marker of where the meaning
  changes. Numbering by shard row keeps one meaning, never rewrites an existing control, still
  "continues the numbering", and makes `index.csv.source` (which ends in the row) the single link
  from image index to raw file. Rejected: renumbering the existing controls to match the accepted
  index, which the prompt forbids; and dropping the de-duplication to preserve index alignment,
  which the frozen contract forbids. Confirmed by `main` after the fact.
- **The first-2000 check compares by shard row, and reports index drift separately.** The claim
  worth verifying is "same shards, same rows, same conversion"; index alignment is a separate,
  weaker property that de-duplication necessarily breaks. `meta.json.parameters.first_2000_check`
  carries both (`all_match` and `n_index_shifted` / `first_shifted_idx`). Rejected: a single
  boolean, which would have reported `False` for Churches and hidden the fact that every one of
  the first 2000 images *is* the crop of the control PNG of its own row.
- **`to_gray_crop` raises rather than returning a resize flag**; the CLI asks `needs_resize(img)`
  before calling it. Rejected returning `(array, resized)`, because the ticket fixes the signature
  as `to_gray_crop(img) -> np.ndarray[uint8, 192, 192]`.
- **Own QC helpers inside `photos.py`** (contact sheet, intensity histogram, duplicates report)
  rather than importing `ihdm/preprocess/qc.py`, as instructed by the prompt: `qc.py` is T1.1's
  file and does not exist on this branch.
- **`source` column is `"<repo_id>/<shard path>/<row>"`**, e.g.
  `tglcourse/lsun_church_train/data/test-00000-of-00001-b3f98c62a94e5d25.parquet/0`, the literal
  reading of the frozen contract's `"<hf_dataset>/<shard file>/<row>"`.

## 6. Open questions, risks, follow-ups

- **The index shift is now a property of `lsun_church` and it is permanent.** Any future code that
  assumes `NATURAL_CONTROLS/lsun_church/NNNNN.png` is image `NNNNN` of `images.npy` will be wrong
  for 145 of the first 2000 and for every image after row 1855. The correct lookup is the row at
  the end of `index.csv.source`. Severity: low if the rule is respected, silent if it is not.
  Suggested owner: whoever writes a sample-to-raw traceback (T4.x).
- **`load_natural` in the TFM analysis scripts takes `sorted(glob)[:limit]`**, which now reads
  4001 / 4000 files instead of 2000 and includes the one duplicate row that predates this run
  (`lsun_church/01855.png`). Those scripts are outside this ticket and were not touched; anyone
  re-running the CPU analyses should know the folder grew. Severity: low. Suggested owner: `main`.
- **The two LSUN repositories are not versioned by this pipeline beyond the file name.** The shard
  file names carry a content hash, so a silent reupload would change the name and the download
  would fail loudly rather than drift, but no revision pin is recorded. Adding
  `revision=<commit>` to `hf_hub_download` would close this. Severity: low.
- **No `manifest.json`.** `02-engineering-practices.md` §3 asks every CLI for one; the frozen
  dataset layout of `03-data-format.md` §1 lists only four files plus `qc/`. `meta.json` carries
  everything a manifest would (inputs, parameters, git SHA, timestamp, content hash), so no fifth
  file was added. Flagged for `main` in case the layout should gain one.
