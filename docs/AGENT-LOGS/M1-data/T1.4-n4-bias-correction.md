**Decisions taken during the work** (each with the alternative rejected and why):

- **D-T1.4-1 — `n4_correct` returns an `N4Result` (corrected image, log bias field, diagnostics),
  not the bare `sitk.Image` the ticket's signature sketch names.** The sidecar has to record the
  log-field range inside the mask and the QC sheet has to draw the field, so both callers need the
  field that the filter already produced. Returning only the corrected image and recomputing the
  field in the caller was rejected: it would either run the estimate twice or force the caller to
  reach into the filter object.
- **D-T1.4-2 — `N4Config` carries the SimpleITK defaults explicitly and a unit test pins them
  against `N4BiasFieldCorrectionImageFilter()`'s own getters.** Not setting anything at all is the
  most literal reading of "default parameters", but then `meta.json.parameters.n4` could not list
  "every parameter actually used" without querying the filter, and a future SimpleITK whose defaults
  moved would silently change the data. Setting the documented defaults and asserting they equal the
  library's defaults gives both properties. Measured on SimpleITK 2.5.6: iterations `(50,50,50,50)`,
  convergence threshold `0.001`, spline order 3, control points `(4,4,4)`, 200 histogram bins,
  Wiener noise `0.01`, bias-field FWHM `0.15`, mask label 1.
- **D-T1.4-3 — N4 runs on the 400 selected subjects only, not on the whole registered cache.**
  The gate and the seeded draw happen before the slicing and are unaffected by N4 (they read the
  registration sidecars), so correcting the 181 IXI and 16 OASIS-1 volumes that never enter the
  dataset would cost wall time and 4 GB of cache for nothing. Rejected: correcting the full cohort
  "in case the gate moves" — the gate is frozen and the cache is keyed by subject, so a later change
  simply corrects the new subjects on demand.
- **D-T1.4-4 — the site label is written into the N4 sidecar and into
  `meta.json.parameters.sites`; the *registration* sidecar gains it only for subjects registered
  from now on.** The ticket asks for it "in each registered sidecar", but the registered cache is a
  T1.1 artefact and rewriting 997 sidecars would mean re-registering (7 h) or editing files this
  ticket does not own. Rejected: touching the cached sidecars in place — it would desynchronise them
  from the volumes they describe and from T1.1's log. The site is recoverable from `index.csv`'s
  `source` column for every dataset, corrected or not, which is what the per-site table uses.
- **D-T1.4-5 — the per-site table is computed from `index.csv`'s `source` column, not from
  `meta.json.parameters.sites`.** The sensitivity copies were written by pipeline 1.0 and have no
  `sites` key; deriving the site from the raw filename works identically on both, so the before/after
  columns are produced by one code path. Rejected: back-filling `sites` into the sensitivity copies'
  `meta.json` — it would modify datasets the ticket says to keep untouched.
- **D-T1.4-6 — the "uncorrected" checklist is evaluated with schedules refitted on the uncorrected
  training splits**, not with the N4-fitted frozen arrays. Items (iii)–(v) are statements about a
  dataset *and its own matched schedule*; scoring the uncorrected data against N4-fitted schedules
  would measure the correction, not the uncorrected pipeline, and would not reproduce T1.3's
  published outcome. The refit of `ixi_no_n4_W2` and `oasis1_no_n4_W2` costs seconds.

**Assumptions proceeded on** (each also messaged to `main` when made):

- The dilated template brain mask is used as N4's mask exactly as the ticket freezes it, including
  the voxels where the registered volume is exactly zero because they fall outside the acquisition's
  left-right field of view. ITK sets `log(x) = 0` for non-positive `x` inside the mask rather than
  failing, so this is safe; the fraction of masked voxels that are exactly zero is recorded per
  subject in the N4 sidecar (`mask_zero_fraction`) so the size of the effect is auditable. If it
  turned out large, the fix would be to intersect the mask with the acquisition field of view, which
  would be a mask change and therefore a contract change.
