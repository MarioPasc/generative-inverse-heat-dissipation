# T5.1 — Evaluation array: scripts, one-writer caches, plateau-gate job, measured A100 cost

Milestone M5 · mode: single (‖ T3.4, disjoint files) · model: opus55-high, invokes the
`picasso-sbatch` skill · depends on: T4.3 · the submission of the evaluation array itself waits
for the v2 training array and is done by `main`

## Mission

Everything the evaluation of the 30 training runs needs on Picasso, minus the submission. That
means the launcher/worker pair of the evaluation array, one job that writes the shared inputs
once (seed lists, Inception reference features, staged weights), the plateau-gate job, and a
**measured** per-run cost from one A100 timing job. The timing job also answers the open AMP
question of T4.3 §6. All of it goes in an evaluation plan that `main` can submit from the day
the first training task finishes.

## Why

D16 budgets 3.2 s per chain per image (T3.2), but `evaluate_run` samples without autocast and
T4.3 measured 18.3 s/chain on the 3060. If the 3.2 s was measured with autocast, the
evaluation array is under-budgeted by an unknown factor. The training array is being rerun
(D19), so the queue wait is dead time in which this can be settled.

## Ownership

`slurm/eval/**` (new), `ihdm/cli/evaluate_run.py` and `ihdm/metrics/run_eval.py` (only: an
`--amp {off,fp16,bf16}` flag that defaults to today's behaviour, with the sample cache keyed so
that AMP and non-AMP samples never mix, plus any bug the A100 run exposes, each fix with a
test), `ihdm/sampling/chain.py` (only the autocast dtype, if bf16 needs it),
`tests/metrics/test_run_eval.py`, `tests/cli/test_evaluate_run.py`, `tests/sampling/test_chain.py`,
`docs/HARNESSES/metrics.md` (append a section), `docs/RESULTS/evaluation_plan.md` (new), the log
`docs/AGENT-LOGS/M5-evaluation/T5.1-evaluation-array.md`.

## Specification

1. **One writer (`slurm/eval/prepare_eval.sbatch`).** One A100 job, idempotent. It stages
   clean-fid's weights to `/tmp/inception-2015-12-05.pt` from a copy kept under `$HOME`
   (download or rsync it there first; print the path). For each of the four datasets under
   `$FSCRATCH/datasets/spectral_allocation_heat_diffusion_project/` it writes the seed lists
   (`run_eval.ensure_seed_lists`) and `_features_inception_ref.npy` with their sidecars. The seed
   lists' sha256 must equal the ones the same code produces locally (the local `ixi` lists
   already exist, T4.3 §5); if a hash differs, stop and report. It writes at most 24 files into
   the dataset folders and nothing else on FSCRATCH.
2. **Evaluation array (`slurm/eval/eval_array.sbatch` + `submit_eval.sh`).** One task per row of
   `slurm/array/cells.csv`. Per task: stage the weights; build a shadow run directory in
   `$LOCALSCRATCH` (links to the real run's `config.json`, `manifest.json`, `checkpoints/`,
   `grids/`) so that `samples/` and `metrics/` land on local disk; run
   `evaluate_run --ckpts all` with the D16 counts; return one `tar` per run to
   `~/execs/ihdm/eval/<run_id>.tar` in `$HOME`, plus a plain copy of `metrics/summary.json`.
   Dependencies: `afterok:<prepare job>`. The launcher accepts the training array id for an
   optional `aftercorr:` dependency, and can resubmit by index. `--time` comes from item 4.
3. **Plateau gate (`slurm/eval/gate.sbatch`).** `evaluate_run --gate 35000,40000 --n-lsd 500
   --skip-inception` on cells 0 (`ixi_A0_s1`) and 3 (`lsun_church_A0_s1`), dependency
   `afterok` on those two training tasks; `gate.json` copied to `$HOME`. The decision to extend
   stays with `main`. The README states the order: prepare, then gate, then (after `main`'s
   decision) the array.
4. **Timing job.** One A100 job of at most 2 h, on the fixture
   `~/execs/ihdm/fixtures/array_2408239/ixi_A0_s2/`: EMA checkpoints 5,000 and 7,500 of an
   array-1 run (lr 2e-4). Weight quality does not matter for timing; do not copy the fixture onto
   FSCRATCH. Measure s/chain at batch 32 and 64 with `--amp off`, `fp16` and `bf16` on the same
   500 training seeds and noise stream, the LSD at 7,500 under each mode, Inception feature time
   for 2k samples, and the gate on 5000,7500. From these derive the per-run cost of the D16 plan
   (8 × 500 + 2,000 + 40 × 50 chains + Inception), a `--time` with 30% margin, and the campaign
   A100-hours for each AMP mode. **Recommend** an AMP mode using the speed-up and |ΔLSD| against
   the `ixi` noise floor 0.047 (`metrics_bracket.md`). The contract default stays `off` until
   `main` decides.
5. **Checks.** Each launcher passes `sbatch --test-only`, without the dependency flags. Local
   functional test of `--amp` on the 3060 against the pilot run
   `$IHDM_DATA_ROOT/_runs_local/pilot_ixi_A0_s1` with tiny counts; the existing fp32 sample cache
   there must survive untouched.
6. **`docs/RESULTS/evaluation_plan.md`.** Timing table, sizing, the AMP recommendation, the
   submission order with exact commands, the file budget in `$HOME` and FSCRATCH, and what T5.2
   collects.
