# T5.2 — Collect the evaluation results into one checked folder

Milestone M5 · mode: single · model: opus55-high · depends on: T5.1, T3.5 · consumers: T6.1
(tables and statistics), T6.2 (figures)

## Mission

One command, `python -m ihdm.cli.collect_results`, turns the scattered outputs of the 30 evaluated
runs into one folder that T6.1/T6.2 read and nothing else. It refuses to produce that folder
unless every integrity check passes. The code is written and tested before the evaluation array
runs, against synthetic outputs that follow the real schemas.

## Inputs (all on Picasso, read-only)

- **Per run** (`slurm/eval/eval_array.sbatch`, T5.1/T3.5): `~/execs/ihdm/eval/<run_id><amp>_summary.json`
  and `~/execs/ihdm/eval/<run_id><amp>.tar`. The tar holds the shadow run:
  - `metrics<amp>/ckpt_<step>.json`, `final.json`, `summary.json`;
  - the `.npy` sidecars;
  - `samples<amp>/…`;
  - links to `config.json`, `manifest.json`, `checkpoints/`, `grids/`, `metrics.jsonl`.

  `<amp>` is `_amp-fp16` under D20.
- **Gates**: `~/execs/ihdm/eval/gate/`.
  - `<run_id>_amp-fp16_gate.json` is the legacy 35k/40k gate (job 2432703).
  - `<run_id>_amp-fp16_gate_<early:06d>_<late:06d>.json` is the pair-named gate, e.g. 55k/60k
    (job 2486891).
- **Run directories**: `$IHDM_RUN_ROOT/<run_id>/`, holding `manifest.json`, `config.json`,
  `metrics.jsonl` and `grids/iter_<N>.png`. `metrics.jsonl` must be read through
  `ihdm.train.validate_run.canonical_records`, because run 11 (`lsun_church_A3_s3`) holds a
  segment abandoned by a resume (D21, `docs/RESULTS/submissions.md` §9).
- **Cell table**: `slurm/array/cells.csv`.

## Output (`--out <dir>`; canonical copies in Picasso `~/execs/ihdm/results/`, the workstation and the SanDisk)

```
results/
├── collection.json          provenance: date, git sha, n_iters, amp, input paths + sha256, check verdicts
├── index.csv                one row per run: index, run_id, dataset, arm, seed, tier, n_iters, amp,
│                            checkpoint_steps, final lsd, kid (+CI), fid (+CI, n_ref), M, M_lp,
│                            D_pix, D_lp, recall, coverage, n_skipped, gate verdicts
├── gates/                   every gate JSON, renamed <run_id>_gate_<early>_<late>.json
└── runs/<run_id>/           summary.json, ckpt_<step>.json (every evaluated step), final.json,
                             manifest.json, config.json, metrics.canonical.jsonl, grid_final.png,
                             the PCA/memorisation .npy sidecars (small; no samples)
```

The samples stay in the tars. Nothing is written on FSCRATCH.

## Integrity checks (all must pass; `--allow-missing` only for dry runs)

1. All 30 cells of `cells.csv` are present, and each summary's run identity (run_id, dataset, arm,
   seed) matches its row.
2. Every summary's `checkpoint_steps` equals `run_eval.evaluated_steps(n_iters)`, i.e. 12 steps at
   60k.
3. `sampling.amp` is the same in every run and equals `--amp`.
4. The seed-list digests equal those of `docs/RESULTS/evaluation_plan.md` §5 (already in
   `slurm/eval/expected_seed_lists.csv`).
5. The config and recipe hashes in the summary equal the run's `manifest.json`.
6. The strict JSON has no NaN tokens, and every key of `05-metrics.md` §9 is present.
7. The canonical `metrics.jsonl` ends with `done` at `n_iters` and has no `abort`.

The report goes to `collection.json` and stdout. The exit code is non-zero on any failure.

## Out of scope

Statistics, tables and figures (T6.1/T6.2); any change to `evaluate_run`, the metric definitions,
the trainer or the SLURM workers; submitting jobs.

## Acceptance

1. Tests cover a healthy synthetic 30-run set and each failure mode of the checks. Synthetic
   outputs are generated from the real schemas (reuse the T4.3/T5.1 test fixtures where possible).
2. The full suite is green and `ruff` is clean.
3. A dry run (`--allow-missing`) on the real Picasso inputs that exist today — the two gate
   families, the run directories, no eval summaries yet — prints the expected "missing"
   report. It writes nothing outside `--out` in `/tmp`.
4. `docs/RESULTS/collection.md` gives the exact commands to run the collection on the login node
   and to copy it to the workstation (`$IHDM_DATA_ROOT/../results/`) and to the SanDisk
   (`…/spectral_allocation_heat_diffusion_project/results/`).
5. The log is complete and committed; the file table equals the diff.
