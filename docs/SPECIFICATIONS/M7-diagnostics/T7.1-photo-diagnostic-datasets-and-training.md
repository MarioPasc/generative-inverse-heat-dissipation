## Goal

Two new standard-format datasets that each change exactly one factor of `lsun_church`. The config
factory must train arm A0 on them with the unchanged 60k recipe, and must leave the 30 existing
cells byte-identical. Each new cell must pass a smoke test locally and on Picasso. The two
production runs are then **submitted only after `main` says GO**.

## Datasets (`$IHDM_DATA_ROOT/<id>/`, standard format of `03-data-format.md`)

1. **`lsun_church_r128`.**
   - Source: exactly the 4,000 source rows of `lsun_church`, in the same order. They are
     identified by the shard and row recorded in `lsun_church/index.csv`. Same `splits.json`
     indices (`train` 3,200 / `ref` 800 / `seed` 40).
   - Processing: `PIL convert('L')`, then resize the short side to 128 px with LANCZOS, then the
     centre 128×128 crop. This is the paper's `Resize(128)` + `CenterCrop(128)`; the released
     loader is `scripts/datasets.py` lines 36–37.
   - `images.npy` is uint8 `(4000, 128, 128)` and `meta.json.image_size` = 128.
   - Dedup: as in T1.2, but if a 128² crop collides, **record it and do not replace the row**.
     Row identity with `lsun_church` matters more than uniqueness.
2. **`lsun_church_n32k`.**
   - Processing: identical to `lsun_church`, i.e. a 192² native centre crop, grayscale (T1.2,
     `ihdm/preprocess/photos.py`).
   - `ref` (800) and `seed` (40) are **pixel-identical copies** of `lsun_church`'s `ref` and
     `seed` images.
   - `train` = `lsun_church`'s 3,200 train images plus 28,800 new rows: the first accepted rows of
     the `train` parquet shard of `tglcourse/lsun_church_train` (declared in `fetch_hf.py`,
     unused so far). The rule is shard order, SHA-1 dedup against everything already in the
     dataset, and the same acceptance rule as T1.2.
   - In total 32,840 images; `meta.json` records the composition and the row provenance.
3. Both datasets validate with `python -m ihdm.cli.validate_dataset`, which must accept
   `image_size ∈ {128, 192}` and still validate the four original datasets unchanged. Write a QC
   contact sheet for each.

## Config factory (`configs/spectral/arms.py`)

- New dataset ids `lsun_church_r128` and `lsun_church_n32k`. They take **arm A0 only**, are
  photographs, and are not in `EXPERIMENT_CELLS` (a separate `DIAGNOSTIC_CELLS` table).
- `data.image_size` comes from the dataset (128 or 192). The A0 terminal blur is W/2 (64 at
  128², 96 at 192²). The log schedule is σ 0.5 → W/2 with K = 200. At 128 this needs a frozen
  schedule file `schedules/log_W2_128.npy`, built by the same `log_schedule` code that built
  `log_W2`, with an entry in `schedules.json`. Everything else equals the A0 recipe: batch 16,
  lr 1e-4, warm-up 1,000, clip 1.0, fp16 AMP, EMA 0.999, K = 200, σ = 0.01, δ = 1.25σ, cadences.
- **Regression requirement:** for each of the 30 `EXPERIMENT_CELLS` (all seeds), the built config
  equals the base commit's, compared by the same canonical serialisation the trainer hashes into
  `config_sha256`. This needs a test.

## Definition of done

1. Both datasets are built, validated, and have QC sheets. Row identity holds for r128, and
   `ref`/`seed` pixel identity holds for n32k; both are tested or scripted, with the evidence in
   the log.
2. The config factory extension and `log_W2_128` exist, the 30-cell regression test passes, and
   the full test suite passes.
3. A local CPU smoke (`CUDA_VISIBLE_DEVICES=""`, a few iterations) and the Picasso smoke pass for
   both cells.
4. The production command is ready. After GO: submitted, with job ids and the first-task check in
   `docs/RESULTS/diagnostic_training.md`.
5. Log `docs/AGENT-LOGS/M7-diagnostics/T7.1-photo-diagnostic.md` from `docs/AGENT-LOGS/TEMPLATE.md`;
   everything committed.
