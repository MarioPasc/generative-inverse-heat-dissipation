# T1.5 — Stratify the IXI subject split by site; rebuild, refit, re-sync

Milestone M1 (reopened 2026-09-23) · mode: single · model: sonnet5-xhigh · depends on: T1.4 · blocks: T3.3's real submission

## Why (decision D18)

T1.4 showed that IXI's remaining coarse-band between-subject variance is largely **between-scanner**
(three sites: Guys 1.5 T Philips, HH 3 T Philips, IOP 1.5 T GE). The current seeded random split
gives train Guys/HH/IOP = 49.7/37.5/12.8% against ref = 57.5/30.0/12.5%. Every arm is scored
against the same reference, so arm contrasts are unaffected, but an unbalanced reference shifts the
absolute LSD/KID floor in exactly the octave the claim is about. The [Experiment-Reviewer] asked
for a site-stratified split before any run starts; it costs minutes now.

## Specification

1. `ihdm/data/format.py: split_by_subject(subjects, rng_seed=2026, train_frac=0.8, n_seed=40,
   strata: dict[str, str] | None = None)`. With `strata`, the 80/20 partition is drawn **within each
   stratum** (largest-remainder rounding so the totals stay 320/80 for 400 subjects), and the
   `n_seed` seed subjects are allocated to strata proportionally to the reference counts (largest
   remainder), drawn with the same rng inside each stratum. `splits.json` gains
   `"strata": {"<subject>": "<stratum>"}` and a `"strata_mix"` block with the counts per split and
   stratum; the `"rule"` string says "stratified by site". **`strata=None` must reproduce the
   current split byte-for-byte** (regression test on the synthetic fixture and on the archived
   `oasis1` and photograph `splits.json`).
2. `ihdm/cli/preprocess_mri.py`: for `ixi`, `strata = sites` (the site parsed from the filename,
   already in `meta.json.parameters.sites`); OASIS-1 (one scanner) and the photographs are
   unchanged. Rebuild `ixi` (N4, from `_cache/registered_n4/`) and `_sensitivity/ixi_no_n4`
   (`--no-n4`, from `_cache/registered/`) with the new split; assert the two share subject lists
   and splits; print the site mix per split. The 400-subject selection itself is unchanged.
3. `build_schedules` (refits `ixi_W2`, `ixi_W8`; the other five are unchanged and must keep their
   hashes) and `profile_data` + `fig_data` regenerated; `data_profile.md` updated (per-site table
   again; the site-mix table per split added).
4. `bash slurm/setup/sync_data.sh` to re-sync `ixi` to Picasso; verify the hash line.
5. Tests: stratified proportions per stratum within ±1 subject; seed allocation sums to 40;
   disjointness; determinism; the `strata=None` regression; the CLI's site-mix print.

## Acceptance

1. `ixi` and `_sensitivity/ixi_no_n4` validate; `splits.json` carries `strata_mix` with train and
   ref within ±1 subject of proportional per site; subject lists identical between the two.
2. `schedules/` refit; only the two IXI arrays changed; all 30 cells build.
3. `data_profile.md` regenerated; Picasso `ixi` hash matches.
4. `pytest -q -m "not integration"` green; `ruff` clean; log written.
