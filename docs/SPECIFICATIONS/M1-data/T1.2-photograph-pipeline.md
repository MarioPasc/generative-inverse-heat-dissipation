# T1.2 — Photograph pipeline: fetch to 4000, grayscale, centre crop, splits, QC

Milestone M1 · mode: parallel with T1.1 · model: opus5-high · depends on: T0.1 · unblocks: T1.3

## Mission

Produce `$IHDM_DATA_ROOT/lsun_church/` and `$IHDM_DATA_ROOT/lsun_bedroom/` in the standard format:
4000 grayscale 192 × 192 centre crops each, taken from the same Hugging Face shards as the existing
2000-image controls, deterministic row selection, image-level splits, validated, with QC sheets.

## Ownership

`ihdm/preprocess/photos.py`, `ihdm/preprocess/fetch_hf.py`, `ihdm/cli/preprocess_photos.py`,
`tests/preprocess/test_photos*.py`; output folders `$IHDM_DATA_ROOT/{lsun_church,lsun_bedroom}/`;
the raw folders `/media/mpascual/MeningD2/NATURAL_CONTROLS/{lsun_church,lsun_bedroom}/` may gain
new PNGs and a dated addendum in `NATURAL_CONTROLS/README.md`. Do not touch `ihdm/preprocess/qc.py`,
`mri.py`, `registration.py`, `raw_mri.py` (T1.1's).

## Inputs

- Existing controls: 2000 grayscale PNGs per set at the raw folders above, fetched 2026-09-21/22
  from `tglcourse/lsun_church_train` (test shard, 6312 rows) and `pcuenq/lsun-bedrooms` (test
  shard, row count unknown). Read `NATURAL_CONTROLS/README.md` and any fetch script there first.
- Hugging Face access: `huggingface_hub` + `pyarrow` (parquet) in the `ihdm` env; the user is
  logged in as `mpascualg` if a token is needed.

## Specification

1. **Fetch** (`fetch_hf.py`): list the parquet files of the shard, read rows in shard order,
   decode the image bytes with PIL, keep rows whose short side is ≥ 192 px, and stop at 4000
   accepted rows. The first 2000 accepted rows must coincide with the existing PNGs (verify by
   pixel equality on 20 of them after the same grayscale conversion; if they do not, message
   `main` and proceed with the shard-order rule, recording the discrepancy). If the Bedrooms
   test shard yields fewer than 4000 usable rows, continue into the first train shard and record
   the shard/row provenance per image. Save new PNGs next to the existing ones (`NNNNN.png`,
   continuing the numbering) so the raw folder stays the source of truth, and append a dated
   addendum to `NATURAL_CONTROLS/README.md` (rows, shards, date).
2. **Process** (`photos.py`): `to_gray_crop(img: PIL.Image) -> np.ndarray[uint8, 192, 192]`:
   `convert("L")`, then, for a 256-px short side, the centre 192 × 192 crop; images whose short
   side exceeds 256 are first resized so the short side is 256 (LANCZOS) — record how many needed
   this (expected 0 for LSUN). No other resampling.
3. **Index and splits**: `subject = image id` (`church_00000`), `slice = 0`, `z_mm = nan`,
   `source = "<hf_dataset>/<shard>/<row>"`; `split_by_subject` over the 4000 ids with rng 2026
   (3200/800/40). Duplicate detection: SHA-1 of the cropped array; duplicates are dropped and
   replaced by the next rows so that the count stays 4000; record the number.
4. **QC**: `qc/contact_sheet.png` (64 random images with split labels), `qc/intensity_hist.png`,
   `qc/duplicates.md`.
5. **CLI**: `python -m ihdm.cli.preprocess_photos --set lsun_church|lsun_bedroom [--target 4000]
   [--force]`; writes with `write_dataset`, validates, prints a one-line summary.
6. **Tests**: `to_gray_crop` on synthetic PIL images (256 × 256, 256 × 384, 300 × 300 → resize
   path, 100 × 100 → rejected with `PreprocessError`); the index/split construction on 50 fake ids;
   duplicate handling. Network access is not used in tests.

## Resource limits

At most 4 processes; the GPU is not used; T1.1 holds 20 cores for registration.

## Acceptance

1. Both datasets validate (`validate_dataset == []`), 4000 images each, no duplicates.
2. The first 2000 images equal the existing controls (or the discrepancy is documented).
3. `meta.json` records dataset, shards, rows, crop rule, duplicate count, resize count.
4. `pytest tests/preprocess/test_photos*.py -q` green; `ruff` clean.
5. Log at `docs/AGENT-LOGS/M1-data/T1.2-photograph-pipeline.md` with row counts per shard and wall time.
