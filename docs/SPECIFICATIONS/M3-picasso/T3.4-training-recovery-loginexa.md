model: opus55-xhigh · depends on: T3.3 · blocks: the v2 array submission (done by `main`)

## Mission

Make the training array safe to resubmit. Explain the non-finite losses of array 1 from the
weights that produced them, implement the D19 changes (pre-clip gradient norm, AMP scale, skip
policy, recipe check on resume, lr 1e-4), prove recipe v2 stable with the pre-registered check S,
and run an exhaustive harness of the production training and logging path on Picasso's loginexa
V100s, so that the next array cannot fail for a reason a 25-minute session could have shown.

## Why

Array 1 failed 30/30 (D19, `docs/RESULTS/submissions.md` §7). Every earlier check ran inside
the lr warm-up, the cluster only ever exercised the `ixi` and `lsun_church` A0/A3 cells, and
indices 11–29 never executed a line of Python. Mario asked for an exhaustive loginexa test of
the training and metrics logging before any resubmission.

## Specification

1. **Code (D19, `04` §3.2 amendment).** (a) `grad_norm` = pre-clip norm of the unscaled
   gradients; `amp_scale` on every train line. (b) The skip policy with
   `training.max_consecutive_skips = 10`, `training.max_skips = 100`; abort at the first
   non-finite loss when the GradScaler is disabled. Put the decision logic in a pure, unit-tested
   function or class in `ihdm/train/`. (c) Recipe check on resume, distinct exit code, nothing
   written on mismatch; extension by `n_iters` still works. (d) `optim.lr = 1e-4` in
   `arms.py`. Nothing else in the recipe changes.
2. **loginexa enablement.** The `ihdm` env's torch (2.14.0+cu130) has no sm_70 kernels. Build a
   V100-capable overlay (a venv with `--system-site-packages` on top of the cluster `ihdm` env,
   plus a torch/torchvision build that ships sm_70 kernels, the same torch version if a cu126
   build of it exists) **under `$HOME`, never FSCRATCH**. The file budget is ≤ 13k new files in
   `$HOME`, currently 18.6k of the 35k soft limit; measure it before and after. Script it in
   `slurm/loginexa/`. Every loginexa session runs under `timeout 25m` on a GPU that `nvidia-smi`
   shows free (< 1 GB used). Use at most two of the node's four GPUs at once and never share one
   with another user.
3. **Diagnosis (`docs/RESULTS/nan_diagnosis.md`).** Fixtures:
   `~/execs/ihdm/fixtures/array_2408239/{ixi_A0_s1,lsun_church_A3_s1}/checkpoints-meta/checkpoint.pth`
   at steps 1383 and 1368. The guard saved them after the non-finite step, which the GradScaler
   turned into a no-op, so their `model` weights are the weights that produced the non-finite loss
   (the GradScaler state is not in the released checkpoint). The fixtures also hold `config.json`
   (v1, lr 2e-4), `metrics.jsonl` and `grids/seeds.npy`. Measure on those weights, in fp16
   autocast and in fp32, over many training batches and levels: the fraction of
   batches with a non-finite loss, the first module whose fp16 output overflows (forward hooks),
   per-module max |activation| against the fp16 limit, parameter norms and finiteness. Classify the
   array-1 event as fp16 forward overflow, true divergence, or other, with the evidence.
4. **Stability check S (pre-registered, D19).** Recipe v2 on loginexa, `ixi,A0,s1` and
   `lsun_church,A3,s1` from scratch to step 4,000. Production config; only `resume_every` may be
   lowered, to chain 25-minute sessions. Pass = zero `skip`/`abort` events in both runs and an eval
   loss at 4,000 below the one at 1,000. Report the loss, pre-clip norm and scale traces against the
   v1 same-seed curves in the fixtures. If S fails, set lr = 5e-5 and repeat S once. If it fails
   again, stop and message `main`.
5. **Exhaustive loginexa harness (`docs/RESULTS/loginexa_harness.md`, PASS/FAIL per item with
   verbatim output).** H1 environment (capability 7.0; fp16 autocast forward and backward of the
   real U-Net; `pytest tests/train -q`). H2 **all 30 cells** through the real worker
   (`slurm/array/train_array.sbatch` run with bash and SLURM variables set by hand, `N_ITERS=2`):
   decode, config, schedule hash, data hash, finite loss at batch 16 on the V100. H3 full
   artefacts and cadence on one MRI and one photograph cell with shortened cadence (log 10,
   eval 50, ckpt 100, resume 50, grid 100, `n_iters` 300). It must pass H-TRAIN §2–§3, a
   line-by-line schema check of `metrics.jsonl` (every kind, every key, no NaN tokens, a pre-clip
   `grad_norm` that varies, `amp_scale` present) and a check of the manifest (`lr` 1e-4), the
   grids (look at the PNG), `full_final.pt` and `DONE`. H4 resume after SIGTERM, extension
   300 → 400, and the recipe-mismatch abort. H5 the skip path and the abort path on the GPU, with
   the non-finite loss injected by a test-only mechanism that production cannot trigger. H6
   downstream: `load_ema_model` on the H3 checkpoints and
   `python -m ihdm.cli.evaluate_run --run <H3 run> --ckpts 200,300 --n-lsd 16 --n-final 16 --n-seeds 2 --n-per-seed 3 --skip-inception`
   plus `--gate 200,300`, both writing every key with no nan. H7 peak memory and it/s at batch 16
   on the V100.
6. **Docs.** `slurm/array/README.md` (skip policy, recipe check, exit codes);
   `docs/HARNESSES/training.md` (the loginexa harness as a repeatable section);
   `docs/HARNESSES/picasso.md` §7 (loginexa is usable through the overlay).
