# T2.1 — Trainer hooks, arm config factory, checkpoints, manifest, sanity logging, the two fixes

Milestone M2 · mode: parallel with T2.2 · model: opus5-xhigh · depends on: T1.3 (schedule files; code against the contract if they are not merged yet) · unblocks: T2.3, T3.x

## Mission

Make the released trainer run every arm of the experiment from one config factory over the
standard-format datasets, with the artefacts of `04-run-artifacts.md` §3 (manifest, EMA
checkpoints every 2,500 iterations, rolling resume checkpoint, `metrics.jsonl`, sample grids,
`DONE`), seeded, with the two paper-versus-code fixes behind config keys, and with the smoke test
(train twice, resume once) green on CPU.

## Ownership

`train.py`, `scripts/losses.py` (the level sampler only), `scripts/sampling.py`
(`get_initial_sample` prior-noise lines only), `scripts/utils.py` (only if a helper must be added;
prefer not), `configs/spectral/arms.py`, `configs/spectral/smoke.py` (extend; T0.1 created it),
`ihdm/train/**`, `tests/train/**`. Read-only: everything else, in particular `ihdm/sampling/**`
(T2.2's) and `model_code/**`.

## Specification

1. **`configs/spectral/arms.py: get_config(spec)`** exactly as `04-run-artifacts.md` §2, built
   from a frozen dataclass `ArmSpec(dataset_id, arm, seed, overrides)`. Loads the schedule with
   `ihdm.spectral.schedules.validate_schedule` (if T1.3 is not merged in your worktree, code
   against the contract and load with `np.load` + local checks; do not duplicate T1.3's module).
   `training.batch_size` defaults to 64 with a comment "set by the Picasso probe (D4′)".
   Validation: A2p only on photographs; Bedrooms only A0/A3; unknown ids raise `ValueError`.
   Every released key the code reads (survey in `04` §5 and the list in T0.1 item 7) is present.
2. **`ihdm/train/manifest.py`**: `write_manifest(workdir, config, model, data_meta) -> Path` per
   `04` §3.1 (git SHA via `git rev-parse HEAD` with a dirty flag; hostname; GPU name;
   versions; `slurm_job_id` from the environment; schedule name/sha/values; `n_params`); and
   `config_to_json(config)`.
3. **`ihdm/train/logging.py`**: `MetricsLogger(workdir, config)` writing `metrics.jsonl` and
   tensorboard; `log_train(step, loss, losses_batch, fwd_steps_batch, lr, dt, grad_norm)` with the
   per-octave loss (map `fwd_steps_batch` → $\sigma_B$ → octave bin of `05-metrics.md`; average
   `losses_batch` per bin over the window since the last log line), `it_per_s`, `img_per_s`,
   `gpu_mem_peak_gb` (`torch.cuda.max_memory_allocated`, reset per window; 0 on CPU), `wall_s`;
   `log_eval(step, loss)`; `log_event(kind, **fields)`.
4. **`ihdm/train/checkpoints.py`**: `save_ema(workdir, step, model, ema, config) -> Path` writing
   `checkpoints/ema_iter_{step:06d}.pt` per `04` §3.3 (EMA weights copied into a temporary state
   dict without the `module.` prefix; the live model weights are not touched);
   `save_full_final(...)`; `resume_path(workdir)`.
5. **`ihdm/train/grids.py`**: `fixed_seed_images(dataset_root, seed, n=8)` (from the train split,
   saved once as `grids/seeds.npy`) and `save_grid(workdir, step, model_fn, config, heat_module,
   seeds)` producing `grids/iter_{step:06d}.png` with the seeds as the first row and one sample
   per seed as the second row (EMA weights, `prior_noise` as configured, `delta` as configured).
   Reuse the released `get_sampling_fn_inverse_heat` for this; do not copy it.
6. **`train.py`** edits at the hook points of `04` §5 only: seeding at the top of `train()`; the
   data loaders unchanged (they come from `scripts.datasets.get_dataset`); manifest written before
   the loop; the loop keeps the released structure and replaces the checkpoint/sampling/eval
   blocks with the cadences `ckpt_every`, `resume_every`, `eval_every`, `grid_every`, `log_every`;
   per-step timing with `time.perf_counter()` and `torch.cuda.synchronize()` at log steps only;
   NaN/Inf guard (log `abort`, save the resume checkpoint, `sys.exit(3)`); at `n_iters`: final EMA
   checkpoint, `full_final.pt`, `DONE`. Resume: `initial_step` from the released
   `restore_checkpoint`; if `n_iters` in the new config exceeds the saved step, training continues
   (D10). Keep the released `logging.info` lines. The eval block uses the released `eval_step_fn`
   (EMA weights) over 25 batches of the `ref` loader.
7. **`scripts/losses.py`**: `get_label_sampling_function`: upper bound `K + 1` when
   `config.model.get("train_level_max_inclusive", False)`. Nothing else.
8. **`scripts/sampling.py: get_initial_sample`**: after blurring to level $K$, if
   `config.get("sampling") and config.sampling.get("prior_noise", False)`: `x = x + delta *
   torch.randn_like(x)`. Nothing else.
9. **Tests** (`tests/train/`): `test_arms_config.py` (every valid `(dataset, arm)` builds; invalid
   combinations raise; schedule endpoints match `blur_sigma_max`; `blur_schedule[0] == 0`;
   `train_level_max_inclusive` and `prior_noise` present); `test_level_sampler.py` (with the flag,
   level $K$ is drawn; without, never; 10k draws); `test_prior_noise.py` (with the flag, two draws
   from the same batch differ; without, they are equal); `test_smoke_train.py` (smoke config,
   `n_iters=6`, `ckpt_every=3`: run → `ema_iter_000003.pt`, `ema_iter_000006.pt`, `full_final.pt`,
   `DONE`, `manifest.json`, `metrics.jsonl` with `train`/`eval`/`ckpt` lines, `grids/iter_000006.png`;
   then re-run with `n_iters=9` on the same workdir → resumes from step 6 (a `resume` line) and
   writes `ema_iter_000009.pt`); `test_checkpoint_format.py` (keys, no `module.` prefix, schedule
   sha matches). All CPU, < 2 min total.

## Acceptance

1. `python train.py --config configs/spectral/arms.py:ixi,A3 --config.seed=2 --workdir runs/x` starts (may be stopped after the manifest and the first log line if no GPU time is available; record what you ran).
2. `pytest tests/train -q` green; `ruff` clean; the released tests of T0.1 still pass.
3. `git diff` on `scripts/losses.py`, `scripts/sampling.py` shows only the lines named in items 7–8.
4. The run directory layout matches `04` §3 exactly (list it in the log from the smoke run).
5. Log at `docs/AGENT-LOGS/M2-training/T2.1-trainer-hooks-and-arm-configs.md`.
