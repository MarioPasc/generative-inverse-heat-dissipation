# T2.2 — Offline sampler from a checkpoint with seed images

Milestone M2 · mode: parallel with T2.1 · model: opus5-high · depends on: the contracts of `04` §3.3 and §4 · unblocks: T2.3, T4.x, T5.x

## Mission

Implement `ihdm/sampling/` and the CLI `ihdm.cli.sample_ckpt` per `04-run-artifacts.md` §4: load
an EMA checkpoint into the released U-Net, take seed images from a dataset split (`train` or
`seed`) or from an array, build the prior state (blur to `start_level`, optional prior noise),
run the reverse chain in batches and write the samples. This is the only sampling path used by
the metrics.

## Ownership

`ihdm/sampling/**`, `ihdm/cli/sample_ckpt.py`, `tests/sampling/**`. Read-only: `scripts/sampling.py`
(copy the loop into `ihdm/sampling/chain.py` with attribution and parametrise the start level; do
not edit the original), `model_code/**`, `train.py` and `ihdm/train/**` (T2.1's).

## Specification

1. **`ihdm/sampling/loader.py`**: `load_ema_model(ckpt_path, config, device) -> torch.nn.Module`:
   `mutils.create_model(config)` (released), load `ema_state_dict` into `model.module` (the
   released model is wrapped in `DataParallel`), `eval()`, `requires_grad_(False)`; verify the
   checkpoint's `schedule.sha256` equals `config.model.blur_schedule_sha256`, else
   `SamplingError`. `load_run_config(workdir) -> ConfigDict` from `config.json` (T2.1 writes it;
   until merged, build it via `configs.spectral.arms.get_config` from `manifest.json`'s
   `dataset_id, arm, seed` — support both).
2. **`ihdm/sampling/seeds.py`**: `load_seed_images(dataset_root, source, n, rng_seed)` per `04` §4
   (`seed`: one image per seed subject, the slice with `slice == 5` for MRI, the image itself for
   photographs; `train`: `n` distinct indices with `np.random.default_rng(rng_seed)`); returns
   `(uint8[n,192,192], idx[n])`.
3. **`ihdm/sampling/chain.py`**: `SampleRequest` dataclass (`04` §4);
   `prior_state(heat_module, x, level, delta, prior_noise, generator)`;
   `reverse_chain(model_fn, u_K, start_level, delta, generator) -> u_0` (the released update
   $u \leftarrow \text{model}(u, k) + u + \delta\,\epsilon$ for $k = \text{start}, \dots, 1$,
   returning the last mean); `sample_from_seeds(model, config, seeds_u8, request, device)`
   batching over `seeds × n_per_seed` with `torch.inference_mode()`, a `torch.Generator(device)`
   seeded by `request.rng_seed`, results clipped to $[0, 1]$, returned as float32
   `(N, n_per_seed, 192, 192)`; `torch.cuda.empty_cache()` between batches. Optional
   `autocast` under `request.amp` (default False).
4. **CLI** `python -m ihdm.cli.sample_ckpt --run <workdir> --ckpt <name> --source train|seed|file
   [--seeds-file x.npy] --n-seeds N --n-per-seed M [--start-level K] [--delta d] [--batch 64]
   [--rng-seed 0] --out <dir>`: writes `samples.npy` (uint8 rounded), `seeds.npy`, `seed_idx.npy`,
   `request.json` (all arguments + checkpoint sha + git sha + wall time), and a `preview.png`
   (first 8 seeds × up to 4 samples). Prints one summary line.
5. **Tests** (`tests/sampling/`): a tiny model (smoke config, `K=8`, $32^2$) with random weights
   saved in the `04` §3.3 format by the test itself; `load_ema_model` round-trips the weights;
   `reverse_chain` with `delta=0` and a model that returns zeros gives back the prior state;
   `sample_from_seeds` shapes and range; `n_per_seed=3` with the same generator seed is
   reproducible; `prior_noise=False` and `delta=0` makes all `n_per_seed` samples identical;
   `load_seed_images` picks slice 5 per seed subject on the synthetic fixture; a schedule-hash
   mismatch raises `SamplingError`. Mark a test `integration` that loads a real checkpoint from
   `$IHDM_RUN_ROOT/pilot_*/checkpoints/` when one exists (T2.3 will produce it).
